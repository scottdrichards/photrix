# torch/torchvision are PINNED, not left to the default "pip install torch"
# latest, and the pin matters: the default/latest wheel (torch>=2.10, any
# recent cu12x or cu13x index) silently drops kernel support for this box's
# GPU (a Quadro P520, Pascal/GP108, compute capability 6.1/sm_61) —
# `torch.cuda.is_available()` still reports True, but every actual op fails
# at runtime with "CUDA error: no kernel image is available for execution on
# the device". Broke live search sitewide on 2026-08-24 after the venv ended
# up on the latest torch. cu126's sm_60 kernels still run on this sm_61 card
# (same Pascal generation); cu128/cu129/cu130 dropped it. torchvision is
# pinned to the exact release PyTorch pairs with 2.9.x — an unpaired
# torchvision (e.g. whatever installs alongside a newer torch) imports fine
# but conflicts at the ABI level. python3.14 (this venv's interpreter) is too
# new for a cu118 build to exist, or this would use one instead — cu126 is
# the oldest CUDA index that still ships a py3.14 wheel.
